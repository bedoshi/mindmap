# 機能仕様

MindMeister 風のマインドマップアプリケーションの機能仕様。実装の詳細（構成・技術的な決定）は `.claude/skills/mindmap-app-architecture/SKILL.md`、方針決定の経緯は [decisions.md](./decisions.md) を参照。

## 提供形態

| 形態 | 動作環境 | マップの保存先 |
| --- | --- | --- |
| Web 版 | ブラウザ | ブラウザの localStorage |
| Electron 版（デスクトップアプリ） | Windows / macOS / Linux | OS のユーザーデータディレクトリ内の XML ファイル |

- 両者は同じ UI・同じコードで、保存先だけが異なる。
- バックエンド（サーバー）は持たない。
- Windows の Electron 版は自動アップデートに対応する。起動時に GitHub Releases の最新バージョンを確認し、新しい版があればバックグラウンドでダウンロードして、アプリを終了するときにインストールする（確認ダイアログは出さない）。インストーラは GitHub の Releases ページから入手できる。開発用の起動や、自動アップデート対応前のバージョンでは動作しない。

## マップの管理

- 複数のマップを作成・切り替え・削除できる。ツールバーの「☰ マップ」で一覧パネルを開く。
- 一覧は更新日時の新しい順に並び、起動時には最後に更新したマップが開く。マップが 1 つもなければ空のマップを自動で作成する。
- マップのタイトルはルートノード（中心トピック）のテキスト。タイトルを変えたいときはルートノードを編集する。ルートのテキストが複数行のときは、空行を除いた各行（前後の空白は除く）を空白 1 つでつないだものをタイトルにする（マップ一覧の表示や XML 書き出しのファイル名に使う）。
- マップを削除すると元に戻せない（確認ダイアログあり）。開いているマップを削除した場合は、残っている最新のマップが開く。残りが無ければ新しい空のマップを作成する。
- 一覧パネルの下部に現在の保存先（Electron 版はディレクトリの絶対パス）を表示する。
- マップを切り替えると、Undo/Redo の履歴・選択・表示位置はリセットされ、一覧パネルは閉じる。

## マップの構造

- 1 つのマップは 1 つのルート（中心トピック）と、その子孫ノードからなるツリー構造（メインのツリー）。
- メインのツリーとは別に、**フローティングノード**（親を持たない独立したノード）を何個でも置ける。フローティングノードからも子・孫を追加して、別のツリーを作れる。すべて同じマップ（同じファイル）に保存される。
- メインのルートは削除できない。フローティングノードは子孫ごと削除できる。
- メインのルートとフローティングノードをまとめて「ルート」と呼ぶ。ルートは付け替えできないが、座標を動かせる。
- ルート直下のノードはルートの左右に自動で振り分けられ、ノード数（部分木の大きさ）が少ない側に新しいノードが追加される。
- ルート直下の枝ごとに色が割り当てられ、その枝に属する子孫ノードと接続線は同じ色で描画される。
- ノードのテキストは複数行にできる（編集中に `Shift+Enter` で改行）。メインのルートも同様。
- メインのルート以外のノード（子孫ノードとフローティングノード）は、テキストの代わりに**テーブル**をコンテンツとして持てる（テーブルノード）。詳細は「テーブルノード」の節を参照。

## レイアウト

- ルート以外のノードの位置は常に自動計算される（手動配置はしない）。
- ルート（メイン・フローティング）ごとに、そのルートを中心に各部分木を縦に積み上げて左右に広げる。
- ルートの位置は座標（ノード中心のマップ座標、x は右向き・y は下向きが正）で持つ。メインのルートの既定は (0, 0)。ルートを動かすと、その子孫も一緒に動く。
- 新しいフローティングノードの座標は、ダブルクリック（または右クリックメニューで作成）した位置になる。
- ノードの幅はテキスト長（複数行のときは一番長い行）に応じて自動で決まる。高さは行数に応じて増える。複数行のテキストは行ごとに中央揃えで表示する。
- テーブルノードの大きさは行数・列数とセルの内容で決まる（各列の幅はその列で一番長いセルに合わせる）。

## ノードの編集

| 操作 | マウス | キーボード |
| --- | --- | --- |
| 選択 | クリック | 矢印キーで隣のノードへ移動 |
| 子ノードを追加 | ツールバー「＋ 子」 | `Tab` |
| 兄弟ノードを追加 | ツールバー「＋ 兄弟」 | `Enter`（ルート選択時は子を追加） |
| テキストを編集 | ダブルクリック | `F2` / `Space` / 任意の文字キー（その文字から入力開始） |
| 編集の確定 | 他の場所をクリック | `Enter` |
| 改行 | – | 編集中に `Shift+Enter` |
| 編集を確定して子を追加 | – | 編集中に `Tab` |
| 編集のキャンセル | – | `Esc` |
| 削除（子孫ごと） | ツールバー「削除」 | `Delete` / `Backspace` |
| 折りたたみ / 展開 | ノード外側の丸ボタン | – |
| 別の親へ付け替え（ルート以外） | ノードを別のノード（別のツリーのノードも可）の中央付近へドラッグ＆ドロップ | – |
| 兄弟の並び替え（ルート以外） | ノードを別のノードの上端付近 / 下端付近へドラッグ＆ドロップ（そのノードの前 / 後ろに入る） | – |
| ルートの左右を入れ替え | ルート直下のノードを、反対側のノードの上端 / 下端付近、またはルートの左半分 / 右半分へドラッグ＆ドロップ | – |
| フローティングノードを作成 | 余白（ノードの無い所）をダブルクリック / 余白を右クリック →「フローティングノードを追加」「テーブルを追加」。クリックした位置が中心になる | – |
| ルートの座標を移動 | メインのルート / フローティングノードをドラッグ（子孫も一緒に動く） | – |
| 右クリックメニューを開く | ノード（そのノードが選択される）または余白を右クリック | – |
| 選択解除 | 背景をクリック | `Esc`（検索中は検索を終えるだけで、選択は解除しない） |
| 元に戻す / やり直す | ツールバー | `Ctrl+Z` / `Ctrl+Shift+Z`・`Ctrl+Y` |

- ノードを削除すると、直前（上）の兄弟ノードが選択される。上の兄弟がいなければ直後（下）の兄弟、どちらもいなければ親ノードが選択される。
- 新しく追加したノード（フローティングノードを含む）は即座に編集状態になる。
- 既存のノードをダブルクリック / `F2` / `Space` で編集し始めると、既存のテキストが全選択された状態になる（編集中であることがひと目で分かるようにするため）。そのまま入力すると置き換わり、矢印キーを押すと選択を解除してカーソルを動かせる。文字キーで編集を始めた場合は、その文字で置き換えた状態から入力が続く。
- フローティングノードを削除したあとは、メインのルートが選択される。
- テキストが空のまま確定・キャンセルされたフローティングノードは、子が無ければ自動的に削除される（メインのルートは空にできない）。
- ルートの移動とフローティングノードの追加・削除は Undo/Redo の対象。
- テキストが空のまま確定・キャンセルされた末端ノードは自動的に削除される。
- 折りたたんだノードには、隠れている子孫の数がボタンに表示される。
- ドロップ先のノードの上端・下端から高さの 30% の範囲に落とすと兄弟として前・後ろに入り、それ以外（中央付近）に落とすと子として末尾に入る。ドラッグ中は、兄弟として入る位置に緑の線、子として入るノードに緑の枠を表示する。
- ルート（メイン・フローティング）にドロップすると常に子になり、ルートの左半分なら左側、右半分なら右側に置く（線はルートの左端 / 右端に表示する）。ルート直下のノードの前後に兄弟として置いた場合は、そのノードと同じ側になる。どちらの方法でも、子孫は一緒に反対側へ移る。
- 自分自身・自分の子孫へは移動できない。並びも側も変わらない位置へのドロップは無効（枠や線を表示せず、何もしない）。
- 並び替え・左右の入れ替えも 1 回ずつ Undo/Redo の対象。
- IME で変換中に押した `Enter` は確定操作として扱わない（変換の確定のみ）。
- 確定時に前後の空白・改行は取り除く（途中の改行は残る）。
- Undo/Redo の履歴はマップごとに最大 100 件。

### 右クリックメニュー

ノードを右クリックすると、次のメニューが開く。メニューの外をクリックする・`Esc` を押す・ウィンドウの大きさを変えると閉じる。編集中の入力欄の上で右クリックしたときはこのメニューを開かない（Web 版ではブラウザ標準のメニューが開く。Electron 版では何も開かない）。

| 項目 | 対象 | 動作 |
| --- | --- | --- |
| 子ノードを追加 | すべてのノード | 末尾にテキストの子ノードを追加して編集状態にする（`Tab` と同じ） |
| 子にテーブルを追加 | すべてのノード | 末尾に 2 行 × 2 列の空のテーブルノードを追加し、左上のセルを編集状態にする |
| セルを編集 | テーブルノード | 右クリックしたセルを編集する |
| 上に行を追加 / 下に行を追加 | テーブルノード | 右クリックしたセルの行の上 / 下に空の行を挿入する |
| 行を削除 | テーブルノード | 右クリックしたセルの行を削除する（1 行しかないときは選べない） |
| 左に列を追加 / 右に列を追加 | テーブルノード | 右クリックしたセルの列の左 / 右に空の列を挿入する |
| 列を削除 | テーブルノード | 右クリックしたセルの列を削除する（1 列しかないときは選べない） |
| ノードを削除 / テーブルを削除 | すべてのノード | 子孫ごと削除する（メインのルートでは選べない） |

余白（ノードの無い所）を右クリックすると、次のメニューが開く。作るノードは右クリックした位置が中心になる。

| 項目 | 動作 |
| --- | --- |
| フローティングノードを追加 | テキストのフローティングノードを作って編集状態にする（余白のダブルクリックと同じ） |
| テーブルを追加 | 2 行 × 2 列の空のテーブルそのものをフローティングノードとして作り、左上のセルを編集状態にする |

### テーブルノード

- 行 × 列のセルからなる表をコンテンツとして持つノード。テキストは持たない。メインのルートはテーブルノードにできない（タイトルに使うため）。フローティングノードはテーブルノードにできる。
- 最小は 1 行 1 列。セルの内容は複数行にできる（編集中に `Shift+Enter` で改行）。見出し行などの区別は無い。
- 各行の高さは、その行で一番行数の多いセルに合わせる。
- 通常のノードと同様に、子ノードの追加・付け替え・折りたたみ・削除ができる。
- 見た目は深さに関わらず、白地（ダークモードでは暗い面）に枝の色の枠線と区切り線。フローティングノードのテーブルは枝の色を持たないため、ルートの色（ダークモードでは明るい灰色）の枠線にする。セルの文字は左寄せ。
- テーブルのフローティングノードも、ドラッグで座標を動かせる。空のまま確定しても自動では削除されない。
- 行・列の追加 / 削除とセルの編集は、それぞれ 1 回ずつ Undo/Redo の対象になる。

| 操作 | マウス | キーボード |
| --- | --- | --- |
| セルを編集 | セルをダブルクリック / 右クリック →「セルを編集」 | テーブルノードを選択して `F2` / `Space`（左上のセル） |
| 編集の確定 | 他の場所をクリック | `Enter` |
| セル内で改行 | – | 編集中に `Shift+Enter` |
| 確定して次 / 前のセルへ | – | `Tab` / `Shift+Tab`（行の端では次 / 前の行へ。表の端では確定のみ） |
| 編集のキャンセル | – | `Esc` |

- セルの編集を始めると、ノードのテキストと同じくセルの内容が全選択された状態になる。
- テーブルノードを選択して文字キーを押しても編集は始まらない（どのセルに入力するか曖昧なため）。
- 空のまま確定したセルはそのまま空のセルとして残る（テキストのノードのように自動削除はしない）。
- ノードのテキストと同じく、確定時に前後の空白・改行は取り除く（途中の改行は残る）。
- IME で変換中に押した `Enter` は確定操作として扱わない。

## 表示

| 操作 | 方法 |
| --- | --- |
| スクロール（パン） | 背景をドラッグ / マウスホイール（トラックパッドの 2 本指スクロール） |
| ズーム | `Ctrl`+ホイール（ピンチ）/ ツールバーの「−」「＋」/ `Ctrl`+`-`・`Ctrl`+`=` |
| 全体を表示 | ツールバー「全体」/ `Ctrl`+`0` |

- ズーム倍率は 20%〜300% の範囲。
- OS のダークモード設定に追従する。
- Electron 版では、アプリのズームショートカットと衝突しないよう、Electron 標準のページズーム（`Ctrl+=` など）はメニューから外している。

## マップ内検索

開いているマップのテキストを検索し、一致したノードへジャンプできる。

| 操作 | 方法 |
| --- | --- |
| 検索を開く | `Ctrl+F`（ノードやセルの編集中も可。開いているときに押すと検索欄にフォーカスして検索語を全選択する） |
| 次の検索結果へ | 検索欄で `Enter` / 「↓」ボタン |
| 前の検索結果へ | 検索欄で `Shift+Enter` / 「↑」ボタン |
| 検索を終える | `Esc` / マップの何も無い所をクリック / 「×」ボタン |

- 検索欄は画面左上（ツールバーの下）に浮かせて表示する。開くとマップ一覧パネルと右クリックメニューは閉じる。
- 入力するたびに検索し直し、最初の検索結果へジャンプする。
- 検索対象はすべてのノードのテキストとテーブルのセル。大文字・小文字は区別しない。空白だけの検索語では検索しない。
- 検索結果はノード単位（テーブルノードはいずれかのセルが一致すれば 1 件）で、表示順（メインのツリー → フローティングノードの作成順。各ツリーは親 → 子の順）に並ぶ。最後の結果の次は最初の結果に戻る（前へも同様）。
- 検索欄に「現在の位置 / 件数」を表示する。一致が無いときは「0 件」と表示し、前後のボタンは押せない。
- ジャンプすると、そのノードを選択し、ズーム倍率はそのままでノードが画面の中央に来るようにスクロールする。
- 折りたたまれたノードの中にある検索結果へジャンプするときは、祖先の折りたたみを展開する（この展開は Undo の対象）。
- 一致した文字の部分は黄色でハイライトする。表示中の検索結果のノードは、ハイライトを濃い黄色にして区別する。編集中のノードやセルの入力欄はハイライトしない。
- 検索を終えると検索欄とハイライトが消え、検索語は残らない（次に開くと空の検索欄になる）。選択は終えたときのまま。
- 検索中にノードをクリックしても検索は終わらない。

## 保存

- 変更は自動保存される（最後の変更から約 0.6 秒後に書き込む）。
- `Ctrl+S` またはツールバーの「保存」で、待たずにその場で保存できる。
- ツールバーに保存状態を表示する: 保存済み / 未保存 / 保存中… / 保存失敗。
- ウィンドウ（タブ）を閉じるとき・リロードするときにも保留中の変更を書き出す。
- 保存に失敗した変更は捨てずに保持し、次の保存時に再試行する。失敗時はメッセージを表示する。
- マップの切り替え・作成・削除・読み込みの前には、必ず保留中の変更を書き出す。

### 保存先

| 環境 | 保存先 |
| --- | --- |
| Web 版 | ブラウザの localStorage（キー `mindmap.map.<マップID>`、値は XML 文字列とタイトル・更新日時を含む JSON） |
| Electron 版 / Windows | `%LOCALAPPDATA%\mindmap\maps\<マップID>.xml`（通常 `C:\Users\<ユーザー名>\AppData\Local\mindmap\maps`） |
| Electron 版 / macOS | `~/Library/Application Support/mindmap/maps/<マップID>.xml` |
| Electron 版 / Linux | `$XDG_DATA_HOME/mindmap/maps/<マップID>.xml`（未設定なら `~/.local/share/mindmap/maps`） |

- マップ ID は UUID。ファイル名に使える文字は英数字・`_`・`-` に限定する。
- Electron 版では環境変数 `MINDMAP_DATA_DIR` を設定すると、そのディレクトリを保存先として使う（検証用）。
- Electron 版の書き込みは一時ファイルに書いてから置き換えるため、書き込み途中で異常終了しても元のファイルは壊れない。

## 書き出し / 読み込み

- 「書き出し」で開いているマップを XML ファイルとしてダウンロード（保存）できる。ファイル名は `<マップのタイトル>.xml`。
- 「画像書き出し」で開いているマップ**全体**を PNG 画像として保存できる。ファイル名は `mindmap-export-YYYYMMDDHHmmss.png`（書き出した時刻のローカル時刻、24 時間表記。例: `mindmap-export-20261117140509.png`）。Electron 版ではこれがダイアログの初期値になる。
  - 画面のズーム・パン・スクロール位置に関係なく、画面外にあるノードやフローティングノードも含めて全ノードが収まる。画像サイズはマップの大きさに応じて変わり、四辺に余白（40px）を付ける。
  - 既定で 2 倍の解像度で出力する。マップが非常に大きく、Canvas の上限（1 辺 16,384px または総画素数 1 億）を超える場合は、収まる倍率まで自動で下げる。
  - 背景は白で、実行環境のダークモードに関わらず常にライトテーマの配色で出力する。折りたたまれたノードには、隠れているノード数のバッジが付く。テーブルノードは画面と同じく枠線・区切り線とセルの文字を描く（フローティングノードのテーブルの枠線はルートの色）。
  - 複数行のテキスト・セルは、画面と同じく 1 行ずつ描く。
  - 検索中のハイライトや、選択・ドラッグ中の表示は含めない。
  - 編集中の入力途中のテキストやドラッグ中の仮の位置は含めず、確定済みの内容を出力する。
  - 保存先は環境で異なる。Electron 版は保存ダイアログで保存先とファイル名を選ぶ（初期位置は OS のダウンロードフォルダ。キャンセルすると何もしない。保存後に保存先のパスを表示する）。Web 版はブラウザのダウンロードとして保存する（保存先はブラウザの設定で、通常はダウンロードフォルダ）。
  - 画像を作れなかった場合は「画像の書き出しに失敗しました」と表示する。
- 「読み込み」で XML ファイルを**新しいマップとして**取り込み、そのマップを開く。既存のマップは上書きされない。
- Web 版と Electron 版で同じ XML 形式を使うため、ファイル経由で相互に受け渡せる。
- 形式が不正なファイルはエラーメッセージを表示して取り込まない。

## XML 形式

```xml
<?xml version="1.0" encoding="UTF-8"?>
<mindmap version="1">
  <node id="<ルートノードのID>" text="中心トピック" x="0" y="0">
    <node id="…" text="子ノード" x="150" y="-20" side="right" collapsed="true">
      <node id="…" text="孫ノード"/>
    </node>
    <node id="…" text="左側の子ノード" x="-150" y="20" side="left"/>
  </node>
  <node id="…" text="フローティングノード" x="400" y="300">
    <node id="…" text="その子" x="560" y="300" side="right"/>
    <node id="…" text="" x="560" y="360" side="right">
      <table>
        <row><cell>項目</cell><cell>値</cell></row>
        <row><cell/><cell>A &amp; B</cell></row>
      </table>
    </node>
  </node>
</mindmap>
```

| 要素 / 属性 | 意味 |
| --- | --- |
| `mindmap@version` | 形式のバージョン（現在 `1`） |
| `node` | ノード。入れ子で親子関係を表し、子要素の順序が兄弟の表示順。`mindmap` 直下の最初の `node` がメインのルート、2 つ目以降の `node` がフローティングノード（別ツリーの根）。作成順に並ぶ |
| `node@x` / `node@y` | ノード中心のマップ座標。`mindmap` 直下の `node`（ルート）では位置として読み込む（省略時は 0）。それ以外のノードは自動レイアウトの結果を参考情報として書き出すだけで、読み込み時は無視する。折りたたみで非表示のノードには付かない |
| `node@id` | ノードID。無い・重複している場合は読み込み時に振り直す |
| `node@text` | 表示テキスト。改行などは文字参照（`&#10;` 等）でエスケープする |
| `node@side` | ルート直下のノードのみ有効。`left` または `right`。省略時は `right` |
| `node@collapsed` | `true` のとき折りたたみ状態。省略時は展開 |
| `table` | テーブルノードのコンテンツ。`node` の最初の子要素として置く（子ノードの `node` より前）。テーブルノードの `text` は空 |
| `table/row` | 行。出現順が上からの行の順 |
| `row/cell` | セル。出現順が左からの列の順。内容は要素のテキスト（`&` `<` `>` と改行は文字参照 `&amp;` `&lt;` `&gt;` `&#10;` でエスケープ）。空のセルは `<cell/>` |

- ルート直下以外のノードに付いた `side` は無視する（フローティングノードの直下の子には有効）。
- フローティングノードを含まない従来のファイル（`x` / `y` 無し）もそのまま読み込める。形式のバージョンは 1 のまま。
- 不明な要素・属性は無視する（将来の拡張用）。テーブルに対応していない古いアプリでテーブルノードを含むファイルを開くと、テーブルノードはテキストが空のノードとして読み込まれる（形式のバージョンは 1 のまま）。
- 行ごとに `cell` の数が違う場合は、最も多い列数に合わせて空のセルを補う。`row` が 1 つも無い `table` と、メインのルート（`mindmap` 直下の最初の `node`）の `table` は無視する。

- バックエンドによる保存・共有・共同編集
